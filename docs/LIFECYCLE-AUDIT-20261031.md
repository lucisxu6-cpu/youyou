# 插件与固件生命周期审视：2026-10-31

交付版本：插件 0.3.3，固件 1.1.1，协议 1；实测宿主 DeepSeek Harness Desktop 0.2.1-rc.5。目标板为 Waveshare ESP32-S3-DEV-KIT-N8R8。当前是四片桌面裸传感器，尚未装入娃娃、尚未保存身体位置映射。

## 结论与实际状态

发现的问题已修复并安装。42 项自动测试全部通过；真实开发板完成 14 项协议检查、200 帧四路采样和用户实际 USB 拔插验证。名字、唯一会话、启用偏好、校准基线及未配对状态与审视前完整一致。

这证明本次列出的桌面 USB 流程和故障处理通过了相应检查，不代表所有电气故障、所有未来宿主版本或装入娃娃后的动作识别已经验收。没有为测试重新绑定用户的部位，也没有创建、归档或删除用户的聊天。

## 本次修复

1. **校准失败后的恢复**：旧版会清空识别器却继续显示已保存的基线。现在校准不稳定、写盘失败或取消时，保留原基线；设备仍在线则重新建立识别器，先看到稳定松开后才接受新触碰。断线则保持离线，重连后恢复。
2. **聊天首次创建与重试**：并发打开复用同一操作。创建成功但保存关联失败时，在本次进程中保留已创建 ID，重试不重复创建；保存后再改标题与发送开场。开场失败保留待发送标记，仍允许打开原聊天；离线或暂时忙碌不会阻断打开原聊天。归档在异步恢复期间发生时也不会偷偷恢复。
3. **串口边界**：严格限制单行 1024 字节，包括未换行的数据；停止后不再接收同批剩余帧；重复／倒退序号丢弃，跳号清空暂存事实，uint32 回绕正确处理。桥接对板型、采样周期、身份与通道一起检查，枚举去除重复 COM 条目。
4. **时间与状态**：新鲜度、回应间隔、重试和配对超时改用单调计时，系统校时不影响控制逻辑；UTC 时间只用于记录。校准、配对与聊天创建期间拒绝冲突配置操作。保存失败清理临时文件，保留旧配置；损坏或不一致的配置停止加载，不当作首次用户静默清空。
5. **固件命令格式**：START／PING／STOP 必须只有正确命令和精确 nonce。多余参数、嵌入 NUL／CR、超长行不被当作有效命令；合法 LF／CRLF 保持兼容。
6. **底层 Flash 行为**：检查真实 Arduino core 3.3.10-cn 源码，确认启动库会调用 NVS 初始化，错误分支可能擦除 NVS。旧版“运行期完全不写 Flash”的描述因此过宽，需要更正为“业务代码没有主动保存”。1.1.1 通过链接包装返回 `ESP_ERR_NOT_SUPPORTED`，阻止整个 NVS 初始化；通过库提供的 `verifyRollbackLater` 钩子跳过自动 OTA 元数据修改。未启用 Wi-Fi、文件系统、OTA 或任何 eFuse 编程。

## Flash 证据

本次固件程序 301253 字节，静态内存 22772 字节。编译脚本在上传前检查最终 ELF：`__wrap_nvs_flash_init` 和强定义 `verifyRollbackLater` 存在，原 `nvs_flash_init` 实现未链接，`initArduino` 实际调用的是包装与延迟钩子。缺少保护时脚本拒绝上传；直接跳过脚本编译会被宏检查阻止。

上传仍限定在 ota_0 应用区。备份目录 `.tools/backups/pet-upgrade-20261031-164710`。升级前读取前 64 KiB，升级并启动六秒后再次读取，哈希相同；该范围涵盖现有布局中的启动程序、分区表、NVS 和启动选择。正常应用升级仍会擦写应用覆盖的扇区，不能将“应用区以外未改变”描述成“刷写零风险”。

底层 NVS 被有意禁用，Arduino 启动日志可能打印“不支持 NVS 初始化”的诊断；握手与 USB 采样不依赖 NVS。此构建策略只适用于当前 USB 版本；未来增加 Wi-Fi、OTA、存储等功能时必须重新审视，不能默默恢复写入。

参考：[Espressif NVS 文档](https://docs.espressif.com/projects/esp-idf/en/stable/esp32s3/api-reference/storage/nvs_flash.html)。具体启动行为以本机编译使用的 `cores/esp32/esp32-hal-misc.c` 和最终 ELF 为准。

## 仍须明确的边界

- 单路空载值不能可靠证明该片的 V／G／S 线始终连接良好；ADC 通道在线不等于传感器物理自检通过。实际按片配对可确认当时的通道响应，不能替代连续断线检测电路。
- 尚未做装入娃娃后的预压、支撑负载、布料厚度、长期漂移验证；短拍是时序候选，持续受压不能证明真正抓握、抚摸方向或拥抱。
- 本次未让用户重新做完整四步部位配对、全部连拍与所有组合。自动测试和已有两路重叠实测不能冒充这些物理验收。
- 配置损坏会停止加载并保留原文件，需要从已保存的备份排查恢复；不会自行抹掉名字或历史。若进程恰在宿主创建聊天后、电脑关联写盘前崩溃，宿主可能留下一个未关联聊天；当前进程内重试已去重，但不能承诺跨两个存储系统的原子事务。
- 模型服务不可用、额度耗尽、模型文字生成偏差由 Harness／模型层处理。插件确保传递真实、及时的传感器事实，不承诺每条生成文字都严格符合人格或传感器解释。
- 新电脑、其他板型、其他 Harness 版本需要依照文档准备工具和验证兼容性；发布包没有包含原用户凭据、聊天或开发工具缓存。

安装补充检查：Harness/pnpm 对同版本、同路径本地包可能沿用缓存。本次最终发布 0.3.3，并在安装脚本中逐个比较 src、client、bridge、manifest 与安装产物的哈希；不一致则明确失败，要求提升版本后重装。最终 42 项自动测试通过。
