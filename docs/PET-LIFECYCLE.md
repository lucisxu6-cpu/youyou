# 陪伴插件的生命周期

产品约束：这台电脑上的一个宠物档案，只关联一块已确认的设备和一段陪伴聊天。设备身份、宠物名字和聊天身份相互独立；换板不应丢掉陪伴历史。普通用户不输入命令，不调整人格或回应频率。固件 1.1.1 提供四路采样，插件兼容旧三路；生命周期和手势策略都在电脑上。

## 初次相遇

1. 安装插件后始终显示猫咪入口，无板时清楚显示「等待 USB 连接」。不要求用户先开聊天，不自行新建空会话。
2. 插入 USB 后自动发现支持的端口，以随机握手核对产品、协议、固件、板型和通道顺序。验证前不会绑定；多块同类设备时要求仅保留目标设备。
3. 显示「绑定这只小猫」，由用户点一次确认。持久化设备的稳定身份，不用可能变化的 COM 号作为身份。
4. 起名并保存，松手校准。校准失败可以重试，不把受压读数作为基线。再按「部位配对」提示逐片选择头、背、左右爪并保存；位置可随时重新配对。未确定位置也可先文字聊天，四路未配对时不投递部位触碰。
5. 点击「开始陪伴」，使用 Harness 原生会话创建接口建立专属聊天，标题为「名字 · 陪伴」。先保存唯一会话 ID，再设置标题和发送开场。重复点击、请求重试不会另外创建会话；以后回到同一段聊天。
6. 文字由 Harness 现有模型回答；USB 触碰只投递到档案里保存的会话 ID。任何其他聊天都不会因为当前可见就被自动关联。

## 日常与恢复

| 情况 | 行为 |
| --- | --- |
| 点击「去聊天」 | 恢复并显示保存的唯一会话 ID；不依据标题、当前焦点或最近聊天猜测。标题重名、改标题不影响关联。 |
| 浏览别的聊天 | 关联保持，触碰仍只投递原陪伴聊天。不会取消其他聊天的回答。 |
| 陪伴聊天退出当前视图 | 不解绑。需要时通过宿主接口恢复原 Agent；不存在实时 Agent 时丢弃旧触碰，不跨聊天发送。 |
| 关闭 Harness 窗口但程序留在托盘 | 随宿主仍在后台运行。要停回应使用「安静陪一会儿」，完全退出则停止采集。 |
| 完全退出、电脑重启 | 进程和采集停止。再次启动保留设备、名字、校准、部位映射、会话和暂停偏好；恢复原聊天，重新握手。关机期间的触碰不重放。 |
| 拔掉 USB、短暂掉线 | 显示离线、清空待回应事件。仍可去原聊天打字。插回同一板自动恢复，不需要重绑或新会话。 |
| 接入另一块板 | 不自动转移绑定，不把它的读数送给原宠物。需解除设备绑定，再明确绑定与校准新设备。 |
| 暂停触碰回应 | 保存暂停偏好，重启后仍暂停；文字对话和原会话保留。恢复不重复开场白。 |
| 会话归档 | 即使 Agent 仍在内存，也停止触碰投递。显示「恢复原聊天」，只有点该按钮才取消归档，不在后台偷偷恢复。 |
| 暂时无法载入原聊天 | 保留关联，显示可重试状态。读取错误不当作删除，也不创建替代聊天。 |
| 原聊天确实找不到 | 保留设备与名字，明确报错。可在确认后新建陪伴聊天，只有新会话收到触碰；不删除任何旧日志。 |
| 解除设备绑定 | 停触碰回应，清设备、基线和部位映射，保留名字与会话。仍能文字陪伴，换板后重新校准和恢复触碰。 |
| 升级、停用、卸载后重新安装插件 | 停用释放串口并清理客户端监听；升级不擦除用户状态。只要电脑上的宠物状态与 Harness 聊天仍存在，重新启用可恢复。安装包不携带个人状态或聊天。 |

当前版本不支持一个电脑档案下同时养多只宠物，不进行跨电脑或云端绑定同步。复制插件包是复用代码，不会复制原用户的宠物档案。Harness 后续版本的会话与客户端 API 必须重新验证兼容性。

## 可靠性边界

- HTTP 设置操作使用宿主 owner 认证与来源校验。操作白名单、参数校验、请求互斥，避免两个窗口同时修改关联。
- 会话创建后先保存身份，后续异步步骤失败时重试仍复用它。开场提交失败保留待完成标记；忙碌时等待空闲，临时失败最多每 10 秒自动重试一次。暂停、归档或配对期间不自动开场，成功后不重放此前触碰。进程在提交与持久化的极窄边界崩溃时，不能承诺模型响应严格恰好一次，但不会因此自动建立另一段会话。
- 档案损坏时停止加载并保留文件，不能静默清空并重新绑定。
- 只响应新鲜的已识别手势；长按不刷屏，连续触碰合并，模型忙时等待有期限。归档、掉线、采样间断、Agent 不可用时清空队列。
- 持久化只发生在电脑。USB 运行期协议只有握手、采样启停和心跳，不包含擦除、烧录或写 Flash 操作。
