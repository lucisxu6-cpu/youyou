# youyou · USB 陪伴小猫

在 DeepSeek Harness 中显示一只可拖动的黑猫头像。悬停或点击展开菜单，从「陪伴设置」完成连接、起名、校准与开始陪伴；普通用户无需输入命令。

支持 Windows + DeepSeek Harness Desktop **0.2.1-rc.5** + 微雪 ESP32-S3-DEV-KIT-N8R8 + CH343 USB 串口 + `pet_usb` 固件 **1.1.1**（四路，兼容旧 1.1.0 四路和 1.0.0 三路）。插件对 Harness 版本作精确限制，升级宿主后需重新验证 API。设备编号、COM、用户目录、名字和聊天 ID 均不写死。

## 日常使用

1. 接好 USB，点击或悬停在猫咪头像上，进入「陪伴设置」。头像可拖到顺手的位置。
2. 初次使用，点击「绑定这只小猫」，填入名字并保存。已有绑定会保留。
3. 松开所有已连接的感应片，点击「开始校准」，等待约 3 秒。
4. 在「触碰设置」点「开始配对」，依次轻按头部、背部、左爪、右爪对应的片；看到「记住啦，请松开」就松手，自动进入下一步。最后点击「保存位置」。换位置时点「重新配对」，不必改线或重刷固件。
5. 点击「开始陪伴」，自动建立专属聊天。以后「去聊天」始终回到它。可以先文字聊天，保存部位后再进行触碰互动。
6. 「安静陪一会儿」暂停触碰回应，仍可文字聊天。「恢复触碰回应」恢复感应，不重复发开场白。

一个宠物档案始终只关联一段聊天，切换当前聊天不会改变关联。关闭和重开使用原会话；归档后停止触碰回应，点「恢复原聊天」才取消归档。原聊天确实找不到时，必须确认才能新建替代。设备详情里可以重新检测、查看连接状态和解除设备绑定；解绑保留名字与原聊天。多块同类设备同时连接时不会自动选一块。

完整状态与异常处理见完整交付包中的 docs/PET-LIFECYCLE.md。名字、绑定、基线、部位配对与聊天关联保存在电脑 `$DSH_HOME/storages/loveandrobot-pet-usb/state.json`，默认位于用户 `.dsh`。不写开发板 Flash，不复制模型密钥。配置损坏时停止加载，不静默重置。插件升级保留已有状态。

## 角色与节奏

人格固定为亲昵、软萌的黑色大耳猫，珍爱主人，以自然的撒娇与括号里的小心情表达陪伴。认真接住用户说的话，避免客服口吻、重复报数、每句追问和强行卖萌。不用内疚、占有或排斥现实关系来索取陪伴。撒娇程度、称呼、回应频率不作为用户设置。

只把真实 USB 按压当作触碰依据，不将它推断成轻抚、拥抱、人的情绪或实际身体动作。位置是计划安装位置；裸片测试不证明已装在娃娃上。

- 50 Hz 采样，迟滞与去抖在电脑上处理；按住时不漂移基线。
- 根据部位识别短拍、连拍、短按、持续接触、长时间接触及松开，双手可组合。原始按压开始不直接唤起模型；持续接触只在阶段变化时产生候选回应。
- 650 ms 短窗口合并触碰，回应至少间隔 7 秒；模型忙时不抢占，最多保留 12 个事件，6 秒过期，不重放过时触碰。
- 1.5 秒没有新数据即标记失效；断线、采样间断和重连清空待回应事件。
- 校准使用约 3 秒稳定静置数据。当前裸片基线要求 ≥3500、波动 ≤100；装入娃娃后若有预压，应另行评估阈值。

## 安装与复用

最终布局为头部、背部、左手、右手。四根信号线接 IO4、IO6、IO7、IO5；每根线对应哪个部位由可视化配对决定，不写死。三路模式可先安装插件；使用四路需要连接第四片并按安全流程升级到固件 1.1.1，再重新校准。

```powershell
.\install-pet-plugin.ps1
# 仅生成可分发 tgz
.\install-pet-plugin.ps1 -PackageOnly
```

安装脚本使用 Harness 自带的 pnpm 与 CLI，备份 Desktop profile 后通过官方插件入口安装。使用正式 bundle 和 `shell.overlay` 客户端扩展位，不修改宿主内置源码。安装或升级代码后可能需要完整退出并重开宿主；日常操作无需重启。

`client/index.js` 是无需额外编译的 Harness lazy-CJS 模块，复用宿主 React，使用内联 SVG，不依赖在线图片。服务端使用 Node 内置模块与 Windows PowerShell/.NET SerialPort，无其他第三方运行依赖。PowerShell 子进程隐藏运行，执行策略仅作用于单个子进程。

UI 通过 `ctx.connection.fetch.register` 注册固定路由，沿用宿主 owner 身份认证和 Origin/Host 校验，不新增公开控制端口。操作白名单、参数限制与状态更改互斥；不暴露本地诊断令牌。客户端卸载时清除定时器、监听器与在途轮询。

卸载或停用使用 Harness 插件页。停止时关闭串口，固件在心跳中断后最多 5 秒停止上报。「安静陪伴」只停回应，不释放串口；单独采样或烧录前需停用插件或退出 Harness。

## 开发与验证

```powershell
node --check plugin/client/index.js
node --test plugin/test/*.test.mjs
# 仅在插件已停用、串口空闲时检查真实硬件
node plugin/test/hardware-smoke.mjs
```

测试覆盖身份拒绝、长按与噪声、双通道、数据间断、合并/忙碌/过期、状态持久化、设置流程、重复开始去重、UI 参数限制、状态互斥、本地诊断认证，以及首次创建、冷启动恢复、归档/丢失处理和换板保留聊天。发布前还需在真实 Harness 验证菜单、设置按钮和实际模型回应。头像支持键盘、对话框焦点管理与减少动画偏好。

开发者兼容命令：`/pet scan|bind|name 名字|calibrate|start|status|pause|unbind`。一旦关联，`start` 不允许静默迁到其他会话。所有普通操作均有图形入口。

仅调试使用 `node plugin/src/control-cli.mjs inspect`；随机命名管道地址与令牌存于运行期 `control.json`，不要分发。它不执行任意代码、不读取模型密钥。电气阈值在 `cordis.patch.yml`，部位时间规则在 `src/body.mjs`，供装配验证调整，不作为用户的性格或节奏设置。USB 身份检查用于兼容性与设备选择，不是防克隆认证。


四个部位的场景、时间规则、识别边界与接线详见完整交付包 docs/TOUCH-INTERACTIONS.md。设置中显示最近识别与缺失感应区。裸片持续受压只是握持候选，不把 ADC 当作抓握、轻重、拥抱或用户情绪的证明。

部位配对时暂停触碰投递，不影响普通文字聊天；只保存完整的一对一映射。重复按同一片、同时按多片会提示重试。取消、关闭设置、超时或断线不会覆盖旧位置。四路未配对时不推测部位。旧三路固件保留原默认映射，完整配对需升级四路。

0.3.2 审视修复：校准失败恢复原有效配置；聊天首次创建并发与写盘失败可重试；开场失败仍可打开原聊天；离线恢复不重复开场；串口输入有长度上限，计时使用单调时钟。固件 1.1.1 还拦截 Arduino 启动时的 NVS 初始化并跳过自动 OTA 元数据修改。旧固件仅能保证业务代码未主动保存，不能把它的底层启动库当作零写入；建议升级到 1.1.1。详见交付包 docs/LIFECYCLE-AUDIT-20261031.md。

0.3.4 配对反馈：配对中的状态刷新间隔为 100 ms；点击开始后立即刷新并忽略旧请求结果。接触第一帧先显示反馈，正式分配仍保留原去抖和阈值。短触碰反馈保留 450 ms；成功后显示刚识别的部位并等待松开，上方位置同步显示已识别。实际显示延迟还包含采样、请求和渲染时间。

0.3.5 简化配对界面：触碰感应和位置配对合为「触碰设置」。配对时只显示当前一步、即时反馈与第几步；完成或取消后恢复日常设置。常用状态不再显示两组部位或多段说明；重新校准收在「感应不灵？」中。识别规则、保存确认和取消保留原设置的行为不变。

0.3.6 最终审查：首次开场遇到忙碌状态时，恢复空闲后自动继续；暂停或归档时保持安静，临时提交失败最多每 10 秒重试一次，不新建聊天。成功后清空此前的触碰候选。可选诊断文件写入失败不再造成宿主进程未捕获异常。固件仍为 1.1.1。
